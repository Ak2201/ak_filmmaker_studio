# UI / UX audit — 6 Oct 2026

Four read-only audits of the whole app. Each was run in Chromium against
an open build, plus a reading of the code. The coverage:

- Themes: dark and light.
- Widths: 1440, 1280, 768 and 390, with a fresh touch-emulated load at
  390.
- States: no project, an empty project, and the Dragon sample.

Duplicates found by more than one audit are merged. Items already in
`docs/KNOWN-ISSUES.md` are not repeated.

Severity means:

- **Critical:** data loss, or a page that cannot be used.
- **High:** a major feature broken, or very confusing for most users.
- **Medium:** a noticeable bug with a workaround.
- **Low:** polish.

"Confirmed" means reproduced in the browser. "Code" means read in the
source only.

Strike an item through, or delete it, in the commit that fixes it.

| Severity | Count |
| --- | --- |
| Critical | 2 |
| High | 11 |
| Medium | 27 |

What came back clean across all pages:

- no console or page errors (one exception, H6);
- no horizontal page overflow at 390;
- every text node passes AA 4.5:1 in both themes (exceptions M18

## Critical

**C1. Work done with no project open says SAVED, then is lost once a project exists.**
Confirmed on contacts, plan, deliverables, budget, story, breakdown and
write.

- **What happens:** with no project open, every module page writes to
  the bare key, such as `fms_contacts_v1` or `fms_scenes_v1`. That data
  survives a reload, so it looks saved.
- **Why it is lost:** creating a project hides it for good. It is also
  left out of every backup.
- **Cause:**
  - `scopedKey()` falls back to the bare key (`src/lib/store.js:803-815`).
  - `migrateLegacy()` runs once and never adopts that data later
    (`:954-959`).
  - `buildBackup()` reads project buckets only (`src/lib/backup.js:152,177`).
  - The "NO PROJECT SELECTED" banner lives in `wireBlueprintHeader()`
    (`store.js:1110-1166`), and only the blueprints call it. Its wording,
    "your edits won't save", is also untrue.
- **Fix:** do one of these, or both:
  - put the banner on every module page and block editing;
  - adopt the bare data into the first project created.

**C2. write.html freezes for minutes on a feature-length script.**
Confirmed with the sample's 2,361 elements.

- **What happens:** about 187s unresponsive on load. About 143s more on
  every Enter, Backspace-delete, move or add.
- **Cause:** `autosizeAll()` (`src/pages/write.js:1636`) calls
  `autosize()` (`:1620`) once per textarea. Each call writes, reads,
  then writes again, which forces a layout every time. It runs on every
  `render()` (`:1595-1596`, twice), on `fonts.ready` and on `resize`.
  On top of that, every edit re-renders all rows.
- **Measured:** batching all writes, then all reads, then all writes
  took 273ms against 64,040ms.
- **Fix:** batch the measurement, and insert or patch one row instead of
  re-rendering the page.

## High

**H1. Feature Blueprint "Reset this blueprint" erases nothing, and the next edit saves it all back.**
Confirmed.

- **Cause:** `resetData()` calls `loadData({})` (`src/pages/feature.js:1596`).
  `loadData()` (`:1440-1481`) only writes the keys present in the object
  it is given, so an empty object clears nothing.
- **Same flaw in import:**
  - The Feature import (`:1583`) has no confirm and no shape check. It
    merges two films.
  - The Short import does the same (`src/pages/short.js:1621` →
    `loadData` `:1030`). Code.

**H2. In-page `#links` change the address but not the tab.**
Confirmed on the Library's cover cards and its Sections menu; likely on
every tabbed page.

- **Cause:** `src/ui/fragments.js:183-197` calls `preventDefault()` and
  `replaceState()` but never dispatches `hashchange`. `src/ui/tabs.js:206-210`
  only switches tabs on `hashchange`.

**H3. AI shot division sends each scene the previous scene's text.**
Confirmed, request body captured. It happens whenever the script has
text before its first heading, which the sample does.

- **Cause:** `sliceScriptByScene()` (`src/lib/ai.js:98-112`) and
  `aiScenePlan()` (`src/pages/visualize.js:441-447`) keep the preamble
  as slice 0. `sliceScript()` (`src/lib/screenplay-analysis.js:47`)
  drops it, so the two disagree.

**H4. Scenes are matched to the script by position, so a delete or a move mispairs every later scene.**
Confirmed.

- **What happens:** "ADD ALL" then tags 239 elements onto the wrong
  scenes, with no undo. Screen time and the cast matrix go wrong too.
- **Cause:**
  - `pairScenes()` (`screenplay-analysis.js:60`) and `suggestAll()`
    (`:253`), used at `breakdown.js:399` and in `reports.js`.
  - `scenes.js:145,151` move and delete rows without touching the script.
- **Fix:** match by heading or slug, or warn on a mismatch and refuse
  "ADD ALL".

**H5. Breakdown's "Tag an element" name field is 26px wide at every width, and the scene bar stacks into full-width rows.**
Confirmed.

- **Cause:** the global `input, select { width: 100% }` (`src/styles/base.css:95-96`)
  beats the flex rules in `modules.css:713-717,783-784`.

**H6. Typing a date into the Plan calendar saves the wrong date and throws two page errors.**
Confirmed.

- **What happens:** typing `03152026` stored 2024-06-12.
- **Cause:** every segment's `change` calls `refreshCalendar()`, which
  rebuilds the input and puts the caret back on the first segment
  (`src/pages/plan.js:623-632,644-651`).

**H7. Contacts "+ Add person" focuses an existing person's Name field.**
Confirmed.

- **What happens:** the new card is added off-screen, 2,656px above, in
  Cast. Your keystrokes then rename the last person in Post.
- **Cause:** `src/pages/contacts.js:497-502`. It should focus the id
  that `addContact()` returns.

**H8. Touch targets are below 44px across the app; shoot.html's 48px Shot / Part / Dropped buttons render at 36px.**
Confirmed.

- **Cause:** `(max-width:560px) .btn { min-height:36px }`
  (`src/styles/chrome.css:1791-1798`) comes later in the bundle than
  `shoot.css:166` and base.css's `(pointer: coarse)` rule, and wins.
- **Also under 44px:**
  - band pills and controls, 32px;
  - fields, 25-36px;
  - breakdown chip ✕, 14px wide;
  - the write line buttons, 32px;
  - the stripboard selects, 25px;
  - the visualize row controls, 24px;
  - the story beat names, 26px.

**H9. On a phone, the command palette cannot be closed.**
Confirmed.

- **What happens:** under 560px the box is full-screen. "esc" is a
  non-interactive `<kbd>`, and the overlay that closes on a mousedown is
  fully covered by the box.
- **Cause:** `src/styles/palette.css:221-226` and `src/ui/palette.js`
  `build()`.

**H10. Typed text is lost on reload or tab close on most module pages.**
Confirmed.

- **Cause:** contacts, plan, edit, deliverables, breakdown, visualize
  and stripboard save on `change` only. Story debounces for 600ms with no
  flush. Only write.js flushes on `pagehide`.
- **Where:** `contacts.js:513`, `plan.js:660`, `edit.js:315`,
  `deliverables.js:264` and `story.js:633-636`.

**H11. The step rail sits under the top band on the blueprints; its top is always hidden at 1100px and wider.**
Confirmed.

- **Cause:** it uses `top: var(--s8)`, 64px, instead of the measured
  band height, which is 128-162px (`src/styles/chrome.css:568-571,588-590`).
